# NewAPI 二级路由接入其他项目安装部署指南

本文说明如何保留 NewAPI 的根路径，同时把另一个项目挂载到同一域名的二级路径。以下示例使用 `/studio/`：

```text
https://panel.example.com/          -> NewAPI
https://panel.example.com/api/*     -> NewAPI API
https://panel.example.com/v1/*      -> NewAPI Relay API
https://panel.example.com/studio/*  -> 另一个前端项目
```

最终由 Nginx 统一提供公网入口。NewAPI 和另一个项目只需监听本机端口或 Docker 内网端口，不应分别暴露公网域名。

## 使用前提

请先确定以下参数，并在后续配置中替换示例值：

| 参数 | 示例值 | 说明 |
| --- | --- | --- |
| 公网域名 | `panel.example.com` | 浏览器实际访问的域名 |
| NewAPI 地址 | `127.0.0.1:3000` | NewAPI HTTP 服务地址 |
| 另一个项目地址 | `127.0.0.1:3002` | 前端开发服务或独立 Web 服务地址 |
| 二级路径 | `/studio/` | 必须以前导和结尾 `/` 包围 |

另一个项目必须可信。挂载到同一 origin 后，该项目的 JavaScript 可以调用 NewAPI 的会话刷新接口并获得当前用户的短期访问令牌。第三方或不可信项目必须使用独立域名和标准 SSO，不能使用本文的同源方案。

## 1. 启动 NewAPI

仓库已有 `docker-compose.yml` 时，可在仓库根目录启动：

```bash
docker compose up -d
docker compose ps
curl http://127.0.0.1:3000/api/status
```

生产环境至少应配置：

```env
SESSION_SECRET=<高强度随机字符串>
SESSION_COOKIE_SECURE=true
SESSION_COOKIE_TRUSTED_URL=https://panel.example.com
# TRUSTED_PROXIES=<NewAPI 实际看到的 Nginx 直连 IP 或 CIDR>
```

如果 Nginx 与 NewAPI 都是宿主机进程，可设置 `TRUSTED_PROXIES=127.0.0.1`。如果二者位于同一个 Docker 网络，应填写反向代理容器所在网段，而不是公网客户端网段。可通过 `docker network inspect <网络名>` 查看网段。

本地纯 HTTP 联调使用：

```env
SESSION_SECRET=<本地随机字符串>
SESSION_COOKIE_SECURE=false
# 本地 HTTP 模式不要设置 SESSION_COOKIE_TRUSTED_URL
```

修改环境变量后重启 NewAPI：

```bash
docker compose up -d --force-recreate new-api
```

## 2. 准备另一个项目

另一个项目需要支持在 `/studio/` 下运行，至少检查以下三项。

### 2.1 构建资源前缀

Vite、Rsbuild 或其他构建工具的资源 base 应设置为 `/studio/`。例如 Vite：

```ts
import { defineConfig } from 'vite'

export default defineConfig({
  base: process.env.VITE_BASE || '/',
})
```

构建命令：

```bash
VITE_BASE=/studio/ bun run build
```

Windows PowerShell：

```powershell
$env:VITE_BASE='/studio/'
bun run build
```

不要在代码中写死 `/assets/...`、`/icons/...` 或 `/plugins/...`。这些地址会请求站点根路径，可能被 NewAPI 接收。应使用构建工具提供的 base URL，例如：

```ts
const logoUrl = `${import.meta.env.BASE_URL}icons/logo.png`
```

### 2.2 前端路由前缀

使用 Browser History 路由时，需要把 `/studio` 配置为路由 base。React Router 示例：

```ts
const basename = import.meta.env.BASE_URL.replace(/\/$/, '') || '/'

createBrowserRouter(routes, { basename })
```

其他路由库应配置等价的 `basepath` 或 `basename`。否则直接刷新 `/studio/image` 等深层页面时会出现 404。

### 2.3 API 使用同源相对地址

另一个项目应调用 `/api/...`，不要写 `http://127.0.0.1:3000/api/...` 或另一个公网域名：

```ts
const api = axios.create({
  baseURL: '',
  withCredentials: true,
})
```

这样开发和生产请求都通过统一入口转发，不需要额外配置 CORS。

## 3. 安装 Nginx

Ubuntu 或 Debian：

```bash
sudo apt update
sudo apt install -y nginx
sudo systemctl enable --now nginx
```

CentOS、Rocky Linux 或 AlmaLinux：

```bash
sudo dnf install -y nginx
sudo systemctl enable --now nginx
```

## 4. 生成二级路由

在 Nginx 的 `http` 块中加入 WebSocket 连接映射。Ubuntu/Debian 通常可以新建 `/etc/nginx/conf.d/newapi.conf`，并把下面的完整配置写入该文件：

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

upstream newapi_backend {
    server 127.0.0.1:3000;
    keepalive 32;
}

upstream canvas_backend {
    server 127.0.0.1:3002;
    keepalive 16;
}

server {
    listen 80;
    server_name panel.example.com;

    client_max_body_size 100m;

    # 统一补齐结尾斜杠，避免相对资源路径错误。
    location = /studio {
        return 301 /studio/;
    }

    # proxy_pass 结尾的 / 会去掉 /studio/ 前缀：
    # /studio/assets/app.js -> 上游 /assets/app.js
    location ^~ /studio/ {
        proxy_pass http://canvas_backend/;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Prefix /studio;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;

        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        proxy_buffering off;
    }

    # 其余路径全部保留原 URI 交给 NewAPI。
    # 此处 proxy_pass 没有结尾 /，因此 /api 和 /v1 不会被改写。
    location / {
        proxy_pass http://newapi_backend;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;

        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
        proxy_buffering off;
    }
}
```

检查并加载配置：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

NewAPI 前端默认会在顶部导航显示“画布”入口，点击后以整页方式进入 `/studio/`，不会交给 NewAPI 自身的前端路由处理。管理员可在“系统设置 → 站点 → 顶部导航”中关闭该入口。

此配置适用于“另一个项目的服务从根路径提供内容”的场景。若另一个项目的上游服务本身已经要求 `/studio/` 前缀，则把：

```nginx
proxy_pass http://canvas_backend/;
```

改成：

```nginx
proxy_pass http://canvas_backend;
```

两种写法不能混用。带结尾 `/` 会剥离 `/studio/`，不带结尾 `/` 会保留原始 URI。

## 5. 静态构建部署方式

如果另一个项目只有构建后的静态文件，不需要启动 `3002` 服务，可以把构建产物放到 `/srv/apps/studio/`：

```text
/srv/apps/studio/index.html
/srv/apps/studio/assets/...
```

然后用下面的 location 替换前述 `location ^~ /studio/`：

```nginx
location = /studio {
    return 301 /studio/;
}

location ^~ /studio/ {
    root /srv/apps;
    try_files $uri $uri/ /studio/index.html;
}
```

`try_files` 的最后一项负责 SPA fallback，因此刷新 `/studio/image`、`/studio/video` 等前端路由时仍会返回 `index.html`。

## 6. Docker 网络部署方式

如果 Nginx、NewAPI 和另一个项目都使用 Docker，建议加入同一个网络，并通过服务名转发：

```yaml
services:
  gateway:
    image: nginx:1.27-alpine
    restart: always
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/newapi.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - new-api
      - canvas
    networks:
      - gateway-network

  new-api:
    # 保留现有 image、environment 和 volumes 配置
    expose:
      - "3000"
    networks:
      - gateway-network

  canvas:
    image: your-canvas-image:latest
    restart: always
    expose:
      - "3002"
    networks:
      - gateway-network

networks:
  gateway-network:
    driver: bridge
```

对应的 Nginx upstream 改为：

```nginx
upstream newapi_backend {
    server new-api:3000;
}

upstream canvas_backend {
    server canvas:3002;
}
```

如果两个项目位于不同的 Compose 文件，应创建一个外部网络，并在两边声明相同网络名：

```bash
docker network create newapi-gateway
```

```yaml
networks:
  gateway-network:
    external: true
    name: newapi-gateway
```

## 7. 接入 NewAPI 登录态

当前 NewAPI 使用“HttpOnly Refresh Cookie + 短期 Bearer Access Token”。另一个项目不能只调用 `/api/user/self` 判断登录态，正确启动流程如下：

1. `POST /api/user/auth/refresh`，浏览器自动携带 HttpOnly Refresh Cookie。
2. 从响应 `data.access_token`、`data.user`、`data.session` 读取当前会话。
3. Access Token 只保存在内存状态中。
4. 调用 `/api/user/self` 时发送 `Authorization: Bearer <access_token>`。
5. Access Token 过期或接口返回 `401` 时，只刷新一次并重试原请求。

最小 TypeScript 示例：

```ts
type AuthBundle = {
  access_token: string
  access_expires_at: number
  user: {
    id: number
    username: string
    role: number
  }
  session: {
    sid: string
  }
}

let authBundle: AuthBundle | null = null

export async function bootstrapNewAPIAuth() {
  const response = await fetch('/api/user/auth/refresh', {
    method: 'POST',
    credentials: 'include',
    headers: authBundle?.session.sid
      ? { 'X-Auth-Session': authBundle.session.sid }
      : undefined,
  })

  if (response.status === 401) {
    authBundle = null
    return null
  }

  if (!response.ok) {
    throw new Error(`NewAPI auth refresh failed: ${response.status}`)
  }

  const result = await response.json()
  authBundle = result.data as AuthBundle
  return authBundle.user
}

export async function getCurrentUser() {
  const request = async () => {
    if (!authBundle) return null
    return fetch('/api/user/self', {
      headers: {
        Authorization: `Bearer ${authBundle.access_token}`,
      },
    })
  }

  if (!authBundle) await bootstrapNewAPIAuth()
  let response = await request()
  if (!response) return null

  if (response.status === 401) {
    authBundle = null
    await bootstrapNewAPIAuth()
    response = await request()
    if (!response) return null
  }

  if (!response.ok) {
    throw new Error(`Get current user failed: ${response.status}`)
  }

  return response.json()
}
```

NewAPI 的 Refresh Cookie 当前使用：

- 名称：`new_api_refresh`
- `HttpOnly=true`
- `SameSite=Strict`
- `Path=/api/user/auth`

Cookie 不需要设置成 `Path=/`。它只需在另一个项目调用 `/api/user/auth/refresh` 和 `/api/user/auth/logout` 时由浏览器自动携带。

退出登录应调用实际接口：

```http
POST /api/user/auth/logout
```

请求应使用 `credentials: 'include'`；如果已知当前 `session.sid`，同时发送 `X-Auth-Session`。退出后清空另一个项目内存中的 Access Token 和用户状态。

## 8. 配置 HTTPS

生产环境必须使用 HTTPS。安装 Certbot 后签发证书：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d panel.example.com
```

签发完成后再次确认 NewAPI 配置：

```env
SESSION_COOKIE_SECURE=true
SESSION_COOKIE_TRUSTED_URL=https://panel.example.com
```

`SESSION_COOKIE_TRUSTED_URL` 必须是精确 HTTPS origin，不能包含 `/studio/` 路径、通配符或结尾路径。

## 9. 验收

先检查路由：

```bash
curl -I https://panel.example.com/
curl -I https://panel.example.com/api/status
curl -I https://panel.example.com/studio/
curl -I https://panel.example.com/studio/assets/<实际文件名>
```

然后在浏览器中验证：

1. 登录 NewAPI。
2. 打开 `https://panel.example.com/studio/`。
3. 确认另一个项目调用 `/api/user/auth/refresh` 返回 `200`。
4. 确认带 Bearer Token 调用 `/api/user/self` 返回当前用户。
5. 刷新 `/studio/image` 等深层路由，页面不应 404。
6. 检查 JS、CSS、图片和字体请求都位于 `/studio/` 下。
7. 在另一个项目退出后，NewAPI 会话应被撤销。

## 常见问题

### `/studio/` 返回 502

Nginx 无法连接另一个项目。确认服务监听地址和端口，并从 Nginx 所在机器或容器测试：

```bash
curl http://127.0.0.1:3002/
```

Docker 场景不要在 Nginx 容器中使用 `127.0.0.1:3002`，应使用 Compose 服务名，例如 `canvas:3002`。

### 首页正常，刷新深层页面 404

另一个项目未配置 SPA fallback，或前端路由没有配置 `/studio` base。开发服务需要启用 history fallback；静态部署使用本文的 `try_files ... /studio/index.html`。

### JS/CSS 请求到了根路径并被 NewAPI 接收

另一个项目构建时没有设置 `/studio/` 资源 base，或者代码写死了 `/assets/...`。修正后重新构建部署。

### `/api/user/self` 返回 401

`/api/user/self` 需要 Bearer Access Token。先调用 `/api/user/auth/refresh` 获取 Access Token，再发送 `Authorization` 请求头。

### `/api/user/auth/refresh` 返回 401

检查浏览器是否已有 `new_api_refresh` Cookie、访问地址是否与登录 NewAPI 时完全同源，以及生产环境是否正确配置 HTTPS、`SESSION_COOKIE_SECURE` 和 `SESSION_COOKIE_TRUSTED_URL`。

### `/api/user/auth/refresh` 返回 Origin 错误

生产环境的公开 origin 必须精确写入 `SESSION_COOKIE_TRUSTED_URL`，例如：

```env
SESSION_COOKIE_TRUSTED_URL=https://panel.example.com
```

不要填写 `https://panel.example.com/studio/`。
